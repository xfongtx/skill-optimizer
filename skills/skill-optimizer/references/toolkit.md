# 工具与账本

三样产物：体检脚本怎么读、出身清单、去向账，外加定律预测表。验证不在这里——校准后由用户拿到真实对话里试。表格里的行全是示例。

## 体检脚本

`scripts/skill-lint.sh <skill 目录>`，只读。每一节都是候选，不是结论：

| 节 | 怎么读 |
|---|---|
| 体量 | 只有常驻文件的行数是直接指标；其余文件先问"常驻还是命中才读"再决定看不看 |
| 硬性措辞密度 | 数字本身不是病。高密度文件里逐条过出身 |
| 历史残留 | 命中的行几乎都该删；例外只有"定义这个症状"的行 |
| 并行编号 | 同前缀 ≥3 个基本坐实。去查这些编号能否由一两条定律推出 |
| 失效链接 | 直接修 |
| 孤儿候选 | 删前另做三查：`grep -rl "<文件名>" <skill 库目录>` 看跨 skill 引用（库目录即 lint 的第二个参数，默认是本 skill 的父目录）；看各 skill 的 frontmatter 是否点名；看记忆目录是否指向它 |
| 含「默认」的行 | 按主题分组，同主题两种口径即自我矛盾 |
| 委托句 | 在 SKILL.md 正文里是留白（合法），在输出模板或提示词范例里是病 |
| 输出契约行 | 逐行问"这一项是交付物本体吗"——四次改造里最确定的收益都出自这里 |
| description | 常驻程度最高的一行。脚本报本条估算 token、全库合计与排名；按 SKILL.md「指针先于内联」逐分支过 |
| 跨 skill 重叠 | 本 skill description 里的触发短语在库内其他 description 里也出现的，逐条问"这句话该归谁"，另一方删掉或改成互斥句 |
| 指针行 | 每条相对链接连同所在行。问"这一行写没写什么情况下读"——只有"另见"的，目标文件基本没人读 |
| 步骤起始行 | 每个编号步骤的第一行。顺着读到句尾，问"agent 能不能判断这一步做完了" |

## 出身清单

拟削减的每条必写句一行。先填 git log 能答的（`git log -S"<原句片段>" --oneline -- <文件>`），剩下的问用户；用户也不确定的，出身填"未知"，处置一律按守卫。

| # | 规则原文（file:line） | 疑似出身 | 依据 | 拟处置 | 用户裁决 |
|---|---|---|---|---|---|
| 1 | `SKILL.md:41` "每个说话人必须写一张选角单" | 堆积 | git 2026-06-12 "补：千人一声"；可由律 4 推出 | 并入律 4 后删原句 | 待 |
| 2 | `SKILL.md:57` "皮肤不写光泽词" | 锁定？ | git 无说明；用户 08-06 对话里点名 | 不动 | 待 |
| 3 | `refs/render.md:12` "配乐必须声明持续" | 未知 | 初始提交即有 | 按守卫：降进失败修法表 | 待 |

给用户看时只给这张表，不附解释；用户只需在最后一列填"删／留／降"。

## 去向账

改完后 `diff` 新旧，旧版每条消失的必写句一行。找不到去处的，就是静默丢失。

| 旧版位置 | 原句 | 去处 |
|---|---|---|
| `SKILL.md:41` | 每个说话人必须写一张选角单 | 并入 execution-model 律 4，推论一句留在按需条款 |
| `SKILL.md:88` | 不是扩展工作流也要写明"本次无需扩展" | 删除，用户裁决 #7 |
| `refs/render.md:12` | 配乐必须声明持续 | 降进 failure-fixes.md 第 3 行 |

顺手做第二件事：把新版入口文件里新写的句子逐句 grep 下层——重写入口时最容易把下层已有的话再抄一遍。

## 定律预测表

新立或修订的每条定律配一条对未见情形的预测，留给用户在真实使用中验证。只能推回原规则、给不出预测的定律，回炉。

| 定律 | 预测（此前未观察过的情形） | 试用结果 |
|---|---|---|
| 被提到即被放大 | 提示词写"极小的雀斑"，出图雀斑仍会偏多偏显 | 待 |
