# 怎么提炼执行者模型

给指挥生成模型的 skill 用。读 skill 的推理模型那一层的机理在 SKILL.md「两层执行者」里，这里不重复。

## 为什么值得做

一个臃肿的 skill 里，规则通常都是对的——它们来自真实翻车。问题是它们以**结论**的形式存在：「不要写 8K」「配乐必须声明持续」「参考图的光会被继承」。结论只能被记忆，不能被推演，所以每遇到一个新失败就只能再加一条，skill 单调增长。

把结论换成**机理**，规则可以归并：「词是检索，效果由训练共现决定」一条就统摄了淘汰词表、体裁锚点、艺术家名拆解三整节内容。遇到全新的失败时，先问「违反了哪条定律」，多数情况能推导出修法的假设——假设仍要在真实使用中验证，不符时修订的是定律。

诚实的边界：四次改造里，可量化的产出改善主要来自输出格式与矛盾消除；定律的收益是**此后每次翻车不再新增一条规则**，是长期的。归并后的推论不必从 skill 里消失——它们可以作为按需条款留着，定律负责的是让它们不再增长、可被解释。

## 定律必须是机理陈述，不是行为规定

这是提炼过程中最容易走偏的地方：

| 不是定律（行为规定） | 是定律（机理陈述） |
|---|---|
| 不要写 `8K`、`highly detailed` | 词是检索，效果由它在训练数据里的共现决定 |
| 每个说话人写一张选角单 | 没写的部分不会被保留，会被即兴 |
| 不要点名"高光"去否定它 | 被提到即被放大——图注只描述显著之物 |
| 提示词不要超过 800 字 | 注意力恒定，每加一句都在稀释其余所有句子 |

判据：**一条定律应该能推出好几条原有规则，并且能预测你还没遇到过的失败。** 只对应一条规则的，是那条规则的换皮；只能推回原规则、给不出预测的，是从规则反推出来的循环。

## 提炼流程

1. **全库捞出所有"实测结论"和"必写句"**，包括失败诊断表的每一行。
2. **逐条问"它为什么成立"**——不是"它有什么用"，是它背后的执行者行为是什么。
3. **按机理归并。** 机理相同的合并成一条。此时会发现散落在四五个文件里的条目其实是同一件事的不同侧面。
4. **反向验证：能否从定律推回原规则？** 推不回来说明定律描述得不准，或者那条规则另有机理。这是必要条件，不是充分条件。
5. **归并到每条定律对应一个独立机理为止。** 数量是气味不是配额：实践里通常落在 5–7 条，显著更多说明还没归并干净，显著更少往往是不同机理被硬揉在了一起。
6. **每条定律写下一条对未见情形的预测**，记入 toolkit.md 的预测表，留给用户在真实使用中验证。给不出预测的回炉。
7. **写进全库最上游、所有路由必读的位置**，并在下层规则处标注它是哪条定律的推论。

## 定律是假设，会过期

定律压缩自小样本，且绑着模型世代——图注是否描述缺席物、否定与长提示的行为，都随训练数据和文本编码器在变。每条定律要答得出「什么证据能修订它」，答不出的不是定律，是信条。复验通道：由定律推导的修法与实测不符时，修订定律本身。下面三套范例各注明了验证过的模型范围，范围之外先复验再沿用。

## 三套已提炼的范例

### 图像模型（五条）

验证范围：作者的图像提示词 skill 在 2026-08 面向的模型——Midjourney，以及 GPT Image／Nano Banana／Seedream 一类高指令遵循模型。律 2 的否定部分在后者已明显弱化，见该条。

1. **词是检索，不是指令。** 效果由训练共现决定，与词典含义无关。`次表面散射` 共现于 CG 渲染图，写它就是检索渲染图。
2. **没有中性词。** 当"说明、约束、免责"写的词照样参与检索。否定失效的程度随模型分化：CLIP 时代的图注几乎从不描述画面里没有的东西，否定近乎无效；带 LLM 文本编码器的高指令遵循模型能部分执行否定，但正向替代仍更可靠——写否定时配正向替代。
3. **被提到即被放大。** 图注只描述显著之物，模型据此反推"既然被写进提示词，它一定值得展示"。这条同时解释了细节词是变焦指令、点名高光反而给高光定位、写实的本质是描述平凡。
4. **体裁锚点是最强杠杆。** 图片按体裁聚类，几个体裁线索就能锁进一个簇，簇内统计免费补齐其余一切。在错误体裁里堆属性词是逆水行舟。
5. **冲突不报错，只稀释。** 矛盾的词被加权混合成糊；注意力恒定。

### 视频模型（六条）

验证范围：作者的视频提示词 skill 在 2026-08 面向的模型。在图像五律之上，增量全部来自**时间维度**：

1. 词是检索，不是指令（同上，体裁锚点同为最强杠杆）。
2. **一次调用是密封的。** 单次生成没有其他提示词的记忆——**遗漏的东西是被重新采样，不是被保留**。跨调用无记忆，除非显式条件化（参考帧、续写、multishot 内的共享上下文）。推论：跨片段重复场景合约是对的，同一片段内重复一个事实是浪费。
3. **运动预算有限，且冲突不报错。** 惰性词偷走运动权重；矛盾指令被平均成一潭死水或静默清零——这正是"提示词好像没起作用"的真身。
4. **只有可见物能渲染，抽象会被视觉补偿。** 模型无法执行"背对""紧张""180度轴线"，它替换成最具体的关联物；两个抽象同时给会产生畸形折中。推论：描述密度才是真正的景别控制。
5. **被提到即被放大，沉默是唯一的降权手段。** 但沉默只对画面外的东西可用——在场实体不管你提不提都会被完整采样，需要显式的活动上限。
6. **生成器有自带的 house defaults**（光轴、蓝夜滤镜、插帧平滑、bloom、自动加对比）。它们不在你的描述里，无法被正向描述取代，每次都回来——这是唯一该写否定的一类，且必须配正向替代。

### 音频模型（六条）

验证范围：Seed-Audio 及同类一次成片音频模型。音频的独特性在于**文本位置直接编码时间**：

1. **文本位置就是时间位置。** 写在前面的先响。这是音频提示词区别于图像和视频的根本性质，也是为什么不需要时间码。推论：相邻两句读作先后发生，要同时就得劈句。
2. **每个声音默认是瞬时事件。** 要贯穿就必须声明贯穿，否则"温暖的管弦乐升起"响几秒就没。
3. **引号内被念出，引号外全是导演指令。** 语法层的硬分工。
4. **没写的部分不会被保留，会被即兴。** 不写选角单就千人一声；提了配乐不写它干什么，它就同一音量铺到尾。静默也必须写出来。
5. **预算是同时存在的层数**，不是字数也不是轮次。多轮对白无害，多条底噪致命。
6. **抽象不可听，只有动作可听。** 艺术家名是这条的极端形态——它检索的是不可控的整体印象。

## 下游是人的产物怎么办

不是所有产物都指挥模型。共创、咨询、教学类的产出给人读——而且**同一个 skill 常常两者都有**（比如诊断对话给人读，设定集锁给下游 agent）。所以按产物逐份判，不给整个 skill 贴一张标签：

- 给人读的产物**跳过"执行者模型"这一步**，它没有对象；
- **"旁枝产出"要重新判定**——讨论过程、方向卡、阶段确认对这类产物就是交付物本体，不能按砍旁枝的刀去砍；
- 但**其余症状全部适用**，尤其是重复层与配额化。实践中这类 skill 的典型病是入口文件把下层模板抄了一遍且数量对不上。

判断方法：**这份产物是给机器执行的，还是给人读的？**——问每份产物，不问整个 skill。
