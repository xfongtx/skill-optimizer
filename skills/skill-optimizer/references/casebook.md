# 判例集

四次真实改造的量化结果，以及改造者自己踩过的坑。后者比前者有用。案例来自作者私有 skill 库，名称已换成类型；这些案例是理论的开发集，不是独立验证——用户同时是理论的共同作者。

## 四次改造速查

| Skill 类型 | 体量变化 | 关键动作 | 这个案例教会了什么 |
|---|---|---|---|
| **图像提示词 skill** | 主路由 536 → 100 行；默认提示词 1300–1600 字 → 400–700 字 | 立五条执行律；三层真实感分解；砍决策记录 | 规则堆积占比高的 skill 能砍掉 60–80%，且**效果显著上升**（用户实测确认） |
| **视频提示词 skill** | 常驻 245 → 186；主路径 375 → 149（−60%）；全库仅 −6% | 四套编号 → 六条执行律；13 行设计简报降为内部 | **总行数不是指标**——全库 3000 行是条件加载的 craft 知识库，不属于削减对象 |
| **声音设计 skill** | 1723 → 1639 行 | 删孤儿文件；三套编号 → 六律；输出 5/6 项 → 3/4 项 | 本身已很克制的 skill，收益主要在**输出格式**而非规则层 |
| **剧本共创 skill** | 入口 208 → 120 行 | 消除三处活的重复层 | 下游是**人**的产物：执行者模型不适用，旁枝产出要重新判定，但重复层病照样有 |

## 各案例的关键教训

**图像提示词 skill：真实感三层分解。** 用户纠正"真实和丑是两码事"之后才建立的模型——解剖层（毛孔、绒毛、生理性血色）+ 光学层（哑光、低反差、颗粒）承担全部真实感，身份层（痣、雀斑、疤）只是角色设计维度。**把可选项写成必需品是防御性堆积的一种隐蔽形态**，它不表现为"规则太多"，而表现为"给所有对象强加同一种特征"。

**视频提示词 skill：skill 与自己开篇原则的矛盾。** 它开篇写着"输出永远是交付物本身，绝不是它的元描述"，却用 HARD GATE 强制在写提示词前输出一份 13 行设计简报。**入口文件的总纲和下层的输出格式是最容易背叛彼此的一对**，每次改造必查这一处。

**声音设计 skill：强制输出空声明。** 原设计要求"不是扩展工作流时也要明确写'本次无需音频扩展策略'"。这是旁枝产出的极端形态——**为了格式完整而输出一句确认自己没内容的话**。正确做法永远是：不需要就沉默。

**剧本共创 skill：活的重复比死的危险。** 声音设计 skill 的孤儿文件是死的（零引用，不会被读到，只是维护负担）；这里的重复是活的——入口和下层都在被加载，而且数量已经漂移（方向卡 6 项 vs 10 项、分场表 9 项 vs 11 列 vs 11 字段三处不一致）。**活的重复会让模型在两个版本间随机选一个，且你无法从产出反推它读了哪份。**

## 改造者自伤判例

这几条是改造者在这四次改造中亲手犯的，全部被用户当场纠正。**它们比成功案例更值得先读一遍。**

### 判例一：单样本过拟合（犯了两次）

第一次：用户给了一张皮肤质感好的参考图，图中人物有痣和雀斑，改造者立刻把"两三处随机小痣与浅雀斑"写进固定句。用户纠正："不能给所有角色强行加入皮肤缺陷，真实和丑是两码事。"

第二次：一轮样张显示平光导致纹理缺失，改造者立刻把默认光线从"均匀柔光"翻转为"45° 侧上方向光 + 光比 2:1"。下一轮出图直接变成次世代 3A 渲染感——雕塑式明暗渐变、发光的耳朵。

**判例：单一样本不翻转默认，两轮以上一致证据才改。** 而且翻转时要问"我是不是从一个极端跑到了另一个极端"——这两次都是。

### 判例二：消除重复时制造新的重复

改剧本共创 skill 时，入口文件被重写为"六关表格 + 指向下层"，同时在表格前加了一句"每一关只写这一关该写的东西（方向阶段只写方向卡，结构阶段只写骨架）"——而下层 protocol 的「避免过早成稿」一节逐字写着同样的话。

**判例：消除重复层的同一个动作里最容易制造新的重复**，因为你正在重写入口、脑子里装着下层的内容。重写完必须再 grep 一遍关键短语。

### 判例三：从外部素材引入越界内容

引入一份 AI 影视团队的实战经验时，改造者把"每次生成四条，用来区分是随机故障还是提示词问题"列为最高优先级建议。用户否决："这是人需要做的判断，skill 做好 skill 需要做的事情就行了。"

同一份素材里同类的还有：肉眼批量定位视觉问题、一个批次挑两条进剪辑、工作区管理。**外部素材（教程、案例、他人经验）里"人的工作流"占比很高**，因为写教程的人是在描述完整生产流程，而 skill 只负责其中一段。

**判例：引入任何外部经验前，先问这个判断靠的是用户的偏好与资源取舍，还是可从交付物与机理推出的诊断——前者留给人。**

### 判例四：用自己的定律审判自己，发现固定句在自伤

改造后期用"被提到即被放大"这条定律回头审自己写的皮肤固定句，发现里面有"光泽只以极小点状出现"——虽然是正向弱化措辞，但它给了"光泽"一个名额，成图脸上就真的多出了反光。同一轮还发现质感文本块自带 14 个连续否定，直接违反自家的否定预算。

**判例：定律立起来之后，第一件事是拿它审判 skill 里所有已存在的固定句。** 自审是常态动作，不是一次性的。

### 判例五：纠错时过冲，整文件重写留下背叛（审本 skill 自身）

按第一性原理审查本 skill 后动手修订。修"把生成模型的否定失效平移到推理模型"这条错误时，措辞直接翻成"推理模型执行'不要做 X'是可靠的"——从一个极端到另一个极端，与判例一同构。同一次修订整文件重写了 SKILL.md，正文改成"变短不是目的"，frontmatter 的 description 却仍承诺"让默认产出更短"；也没做去向账。全部在第二轮审查才发现。

**判例：纠一个方向性错误时，先写下证据支持的"正确区间"再落笔，不写对立面。整文件重写后必做两件事：diff 对账，以及把 frontmatter 当正文的一部分一起审。**

### 判例六：引入外部方法论，矛盾处不二选一

合并一份外部的"给 agent 写文档"方法论。先列矛盾表再动刀：它把"别想大象"用在读 skill 的推理模型那一层，说禁令让被禁行为更易被做出——与判例五纠正后的区间相反，不引；它认为规则平铺成清单是合法安排、没有"从机理推导规则"这一步——那是另一套压缩手段，不引；调用方式、路由、认知负荷是 skill 目录设计，不是校准动作，不引。引入的四项都能从第一层机理推出：指针措辞决定可达（检索成本真实 + 未指定即交还先验）、完成判据（新机理，视频提示词 skill 的模板填空是本地证据，它是第二份独立证据）、便宜查询的副本留指针、弱规则换重词（注意力恒定）。

**判例：引入外部方法论时，先列它与自家定律的矛盾表，矛盾处按证据区间裁决；再逐条问"能否从自家机理推出"，推得出的进症状表与 lint，推不出的留在门外。**

### 判例七：删掉的旁枝以新名字长回来；常驻税看不见（全库审计）

对照一篇讨论"新一代模型该怎么写 skill 与提示词"的文章审全库。视频提示词 skill 上一轮砍掉的 13 行设计简报，这一轮以"四行交付回执"的名字长回来了，而且被写进了五个下层文件和 lint 的报错文案——它是为了逼模型真跑设计过程而设的回报机制，机制本身是对弱模型的补偿。修法不是再砍一次，而是把"跑过了"从回报改成完成判据（每行在每个维度上都判过、改过或留了理由），回执整个删除。同一轮发现本 skill 的症状表里没有 description 这一行：四十多个 skill 的 description 合计数千 token，每个会话都付，最长的一条上千字符，而 lint 只报字数不报排名与合计，症状表把触发词一律当锁定。

**判例：旁枝产出会换名字回来，每次改造都要在"输出契约行"里重新认一遍。凡是全库共同付费的东西（description），单个 skill 的体检看不见，必须报合计与排名。**

### 判例八：压 description 时把分支当同义词删掉

校准一个公开的 skill 打磨类 skill，description 从 690 字符压到 170。复核时发现删掉了两个独立分支："skill 体检／审计"，和"用户只丢来 skill 目录、仓库链接或 SKILL.md 问怎么改"这条隐式触发，还丢了一条负触发。它们看起来像"打磨"的同义词，其实是用户进来的不同入口，删掉会漏触发。

**判例：description 的压缩单位是分支，不是字数。压完把原 description 的每个分支和负触发逐条对一遍，缺一条就补回。**

## 一条元判例

这四次改造里，**用户的每一次纠正都指向同一个方向：改造者倾向于把观察升格为规则，而正确的做法是把观察升格为对定律的修订。** 前者让 skill 增长，后者让 skill 收敛。自审那一次暴露了另一种倾向：纠错时过冲到对立极端。两种倾向的修法是同一个——改动前先写下证据支持的区间，而不是方向。改造者本人的默认倾向就是这个 skill 要治的病。
