# Skill 校准

**核心信念：执行者越强，约束越要精准而稀少。每一条多余的规则都在没收它的能力。** 这是条件句——动刀前先确认这个 skill 实际被谁读（主会话的旗舰模型、低 effort 的 subagent、别人机器上的未知模型），约束疏密配执行者强弱。执行者换代是重新体检的信号：上一代需要的搀扶（强制读全、强制跑检查、每步回报、先问再动）在下一代成了拖累。

臃肿几乎总是同一个过程：每次翻车写成一条"必须"，每条都合理，累积成填表机器。校准的目标不是变短，是**每条留下的规则都答得出自己为什么在**；变短是常见结果。四次真实改造里最确定的收益来自三件事：输出只剩交付物、消灭矛盾与漂移的重复、把可选项从必需品里放回去。立定律的价值主要在防止再次增长，不在立竿见影。

## 两层执行者

**第一层：读 skill 的推理模型**（Claude、GPT、Gemini 等 agent 主模型）。注意力恒定：每一行稀释其余所有行。矛盾不报错：两处相反默认得到不稳定的选边或静默折中，且无法从产出反推。检索成本真实：跳转编号定位失败即静默降级。模板槽位即指令：输出格式里列出的每一项都会被填满，包括"本次无需 X"。未指定即交还先验：没写的不是空白，是判断力——但先验里没有你的环境事实。指针只有措辞在上下文里：目标文件读不读到，由指针写没写触发条件决定，与目标文件多重要无关。步骤以判据收尾：判据模糊时，视野里的后续步骤把注意力拉向"已完成"，当前步骤被提前收工。"被提到即被放大"在这一层只对示例与模板里的内容词成立；禁令对推理模型远比对生成模型有效，但随数量与距离衰减，正向表述仍优于否定——既不拿生成模型的否定失效当理由删禁令，也不拿"禁令有效"当理由堆禁令。

**第二层：读提示词的生成模型**——无推理的检索引擎，定律完整成立。skill 给图像、视频、音频模型写提示词时，读 [execution-model.md](references/execution-model.md)：怎么提炼这一层的执行者定律，附三套范例。

每条规则先归层再审：管执行者行为的按第一层，管提示词内容的按第二层。

## 规则的三种材质

- **可推导**：能从执行者机理推出（"不要写 8K"← 词是检索）。唯一可提炼进定律的一类。
- **偶然事实**：环境与契约——路径、参数、调用顺序、接口字段、交付格式、下游要读的登记表。不可推导，先验不知道，**照单保留**，只清内部矛盾。工具驱动与工作流类 skill 的主体是这一类。例外只有一种：它是某个便宜查询的副本（`--help`、配置文件、目录本身）——留查询指针，不留副本，副本会过期。
- **人的裁量**：用户的偏好与资源取舍（生成几条、挑素材、定投入）。移出 skill。对已产出物的校验、返工路线、回片诊断不是裁量，是本职。

## 流程

**1. 体检，先决定动不动刀。** 跑 `scripts/skill-lint.sh <skill 目录> [skill 库目录]`（末尾两节报 description 的常驻税与跨 skill 重叠，范围是整个库；库目录默认取 skill 的父目录，装在插件里时要显式传真实的库目录），再对照症状表通读；有现成转录（工作区里的、用户带来的翻车对话）就读转录，看模型根本没读的段落、重复读的文件、返工循环。没有现成转录就不制造新的——**本 skill 里没有任何拉起子代理跑用例的步骤**。全部干净就是健康——汇报"不动刀"即结束。

**2. 分诊。** 体量（每次执行都过一遍，还是命中才读——常驻的长相是必写句、预算表、编号体系、scope 补丁，知识库的长相是词汇表、对照表、症状表、体裁配方；常驻 > 主路径 > 条件加载，一个 skill 该降 60% 还是 6% 由此决定）× 材质。只有"常驻 + 可推导"进入提炼；"常驻 + 偶然事实"只清矛盾；条件加载的知识库保留。

**3. 定出身，再动刀。** 每条拟削减的必写句先定出身：防御性堆积（并入定律后删）／低频事故守卫（降进失败修法表，不删）／有意锁定（一字不动）。三者文本同貌。步骤末尾的完成判据句（"每个说话人都有选角单"）归锁定：它定的是这一步做到多深，不是堆积。恢复顺序：**git log → 问用户 → 仍未知按守卫处理**——错删锁定的代价远大于多留一条按需守卫。建出身清单或去向账时读 [toolkit.md](references/toolkit.md)，那里有两张表的形状。

**4. 手术，按收益顺序。**
- **输出格式**：交付物之外一律砍——决策记录、自检表、需求复述、备选版本、"本次无需 X"的空声明。入口文件的输出格式与总纲每次必比。
- **唯一定义**：同一信息全库一个权威出处，其余放指针。矛盾即刻裁决：消灭一边、改成互斥且写明触发条件的按需条款、或写明优先级；禁止的是两个无条件默认并存。
- **指针先于内联**：必读文件没人读，先看指针措辞：写清什么情况下读、读它拿到什么；写不出触发条件的，才把内容提上来。frontmatter 的 description 是常驻程度最高的指针，且全库每条都在同一个会话里同时付费：只写分支级触发与一句边界，同一分支的多个同义词是重复层；触发词里只有用户点名过的才是锁定，其余按堆积处理。压缩的单位是分支，不是字数：用户没点名、但丢来某类材料就该触发的隐式触发是独立分支，负触发也是；压完逐条核对原 description 的每个分支和负触发都还在。
- **三层分置**：必备机制（先验会出错的下针点，一遍读完不丢）／按需条款（写明触发条件）／失败修法（出问题才查）。默认路径只含第一层，任一任务从入口到所需条款 ≤2 跳；合并时规则携带的例外与边界条件随守卫进失败修法表。
- **信任先验**：判据句"删掉这一句，执行者的先验会自己补上吗？会就删"。先验做但做不够的，换更重的词（thorough → relentless），不加句子：同样的 token，注意力不稀释。只对可推导材质有效。
- **词代句**：同一个意思在几处用整句复述的，收成一个模型先验里已有的词（tight、red、默奇律），此后只重复这个词。词的重复不是重复层，意思的重复才是；自造词要付定义成本，先找现成的。
- **完成判据**：每个步骤末尾写可检查、穷尽的完成条件——"每个说话人都有选角单"，不是"处理选角"。判据模糊又观察到抢跑，先磨尖判据；把后续步骤藏起来只在真实上下文边界（子代理、交接）有效，同一会话里拆文件藏不住。
- **留白 = 沉默**：不想锁的维度从产出里消失；需要约束时写事实句，不写委托句、不列选项。
- **执行者模型**：skill 指挥生成模型而没有执行者模型的，立一个；已有的复核。每条定律要推得出至少两条原规则，并**写下一条对未见情形的预测**，留给用户在真实使用中验证——只能推回原规则的定律是循环的。

**5. 记账，然后停下。** 去向账：每条消失的必写句写明去处（并入哪条定律／降到哪张表／经谁确认删除），用 diff 对账——整文件重写最容易静默丢失，也最容易在重写入口时把下层已有的话再抄一遍，重写完再 grep 关键短语；frontmatter 与正文一起审。最后重跑第 1 步，汇报改动与去向账。验证交给用户：把要试的那一条提示词和可操作判据（"放大仍像照片"，不是"效果好"）给用户，由用户在真实对话里跑；不起子代理做 A/B。账本形状见 [toolkit.md](references/toolkit.md)。

## 症状表

| 症状 | 机理 | 处置 |
|---|---|---|
| **防御性堆积**：必写句布满"必须／不可省"，每条对应一次翻车 | 注意力恒定 | 定出身：堆积并入定律，守卫降级，锁定不动 |
| **自我矛盾**：同一问题两种默认；入口输出格式背叛总纲 | 矛盾不报错 | 唯一定义 |
| **配额化**：字数表、分块预算、多档位；U1–U6 式并行编号 | 注意力恒定——预算表是超重的自白 | 合并进定律，编号自然消失。单一交付上限不是预算表 |
| **孤儿与重复层**：无人引用的 index／总览；同一事实两份且已漂移 | 检索成本；矛盾不报错 | grep 零引用只是候选，排除 frontmatter 加载、跨 skill 按名编排、外部记忆指针后再删；活的重复立刻合并 |
| **旁枝产出**：交付物之外的附送品 | 模板槽位即指令 | 只剩交付物 |
| **委托句**：写进给生成模型的产出里的"由你决定" | 第二层无推理 | 写事实句或沉默 |
| **弱指针**：必读文件只挂着"另见 X" | 指针只有措辞在上下文里；未指定即交还先验 | 指针写触发条件：什么情况下读、读它拿到什么 |
| **提前收工**：工作流类 skill 一到某步就模板填空、跳下一步 | 判据模糊，后续步骤拉注意力 | 磨尖判据：可检查、穷尽 |
| **历史残留**：描述改动而非现状的句子（"旧的 X 已……"） | 被提到即续命 | 只描述现状，历史归 git |
| **无关背景**：用户身份与处境、规则的来由（"用户明确要求／厌恶""曾翻车一次"）、脚本或模板已固化的参数被正文复述 | 注意力恒定——不改变执行的句子只稀释其余 | 判据"删掉它，执行会变吗"，不变就删；规则写成直接指令，来由归记忆或 git，参数只留在脚本里 |
| **越界职责**：写进 skill 的人的裁量 | 材质错放 | 移出。外部教程里这类占比极高，引入前先过材质判据 |
| **description 常驻税**：description 长成正文，触发词尾巴列同义词，全库合计随 skill 数线性增长且每个会话都付 | 注意力恒定——description 是唯一一行所有会话都读的文本；库越大每条被看到的份额越小 | 只留分支级触发与一句边界，同义词并成分支；lint 报单条与全库合计 |
| **补偿门**：为弱模型的判断力补的门槛——动手前强制读全套文件、每步回报、每步问一次、交付前附自检报告、"问到有把握为止"的开放式提问 | 未指定即交还先验——强模型自己会读、会检查、会问真正影响结果的事；门槛只剩成本，且会把它拉向提前停工 | 高风险动作（不可逆、花钱、对外）的门保留；其余降成完成判据或删除。用户锁定的提问项（如画幅）照单保留，但收成一轮 |
| **跨 skill 触发重叠**：两个以上 skill 的 description 在同一句话上点亮 | 检索成本——选择在 description 层发生，重叠时随机选边 | 每个短语只归一个 skill；边界写成"X 用 A，Y 用 B"的互斥句，lint 报重叠短语 |

## 回写纪律

- 实测结论回写理论层（修订定律），不回写成新的必写句。
- **增删同一证据标准**：单一样本不翻转默认，也不删除守卫；两轮一致证据才动。
- 翻车记为"案例 + 违反的定律"，进失败修法表，永不进默认流程。
- 用自己的定律审判自己的固定句，每次改完立刻做。

动刀前读 [casebook.md](references/casebook.md)：改造者自己每次都会重犯的自伤判例，读完再落第一刀。
